# Встроенный редактор: план развития

Статус: план. Первый полезный набор относится к направлению 0.4; конкретные сроки не назначены. Возможности ниже не следует считать реализованными.

## Цель и границы

FMStudio должен быть удобен для повседневных правок Lua, рецептов, прототипов и патчей сборки: подсказать поле, объяснить параметр, найти объект и быстро проверить изменение. Пользователь не должен переключаться в другой редактор ради каждой небольшой правки.

Редактор остаётся частью мастерской модов. В первый выпуск не входят отладчик, терминал, Git-клиент, магазин расширений, универсальный рефакторинг и собственная реализация полноценного Lua language server. Открытие файла во внешнем редакторе должно оставаться естественным продолжением работы.

## Что уже есть

По текущему коду editor-tabs.js: вкладки с отдельным состоянием, редактирование текстовых файлов через textarea с наложенной подсветкой, сохранение и конфликт внешнего изменения, диагностика с задержкой и защитой от устаревшего ответа. Tab вставляет два пробела. Структурная проверка Lua не является полным синтаксическим или типовым анализом. Нативная история отмены используется, но её поведение при программных вставках нужно проверить отдельно.

## Ревизия текущего окна редактора

- Сохранить готовую основу: вкладки, подсветку и переход из «Проблем» к файлу. Проверку окна начать с реального Lua-файла и обычного сохранения; прототип нового компонента нужен, только если текущий не выдержит проверок.
- Повторный Ctrl+S после конфликта мог принять новый ETag и перезаписать внешнюю правку. Сохранение теперь ждёт явного выбора, не отправляет параллельные записи и не сбрасывает текст, набранный во время запроса. Эти сценарии покрыты регрессиями.
- В WebView2 проверены сохранение на диск и обычные Undo/Redo. Старая вставка отступа Tab не отменялась. Вставка через нативную команду редактирования возвращает отступ одним Ctrl+Z, что проверено повторно. Shift+Tab оставлен для навигации. Escape закрывает вкладку; обработчик будущих подсказок должен первым получить Escape и оставить вкладку открытой.
- Перед Ctrl+Space отдельно проверить в WebView2: набор → Undo → Redo, программная вставка → Undo и сохранение → Undo → повторное сохранение. Кнопки, положение каретки, выделение и состояние файла должны соответствовать содержимому. Если штатная история не принимает программную вставку, сначала решить эту проблему в редакторе.

## 1. Сначала надёжная основа редактирования

- [ ] Зафиксировать регрессионные сценарии: ввод, многострочная вставка, Undo/Redo, переключение вкладок, сохранение, внешний конфликт и закрытие с несохранёнными правками.
- [ ] Добавить отступ и снятие отступа выделенных строк, перенос с сохранением отступа, комментирование выделения, поиск/замену в текущем файле и переход к строке. Не дублировать уже существующий поиск по моду.
- [ ] Проверить кириллицу, emoji, CRLF/LF, IME, масштабирование и синхронизацию подсветки с прокруткой.
- [ ] Сохранить клавиатурный выход из редактора: Tab не должен безусловно запирать фокус. Подсказки доступны с клавиатуры и не мешают вводу, Escape закрывает всплывающую панель.

Техническое решение: оставить вкладки, сохранение, API и общую оболочку FMStudio. До реализации сложных подсказок сделать ограниченный прототип замены только внутреннего поля редактора на готовый компонент. Выбор компонента принять после проверки размера локальной поставки, лицензии, WebView2/WebKitGTK, CSP, доступности и Undo/Redo. Сравнить с сохранением textarea; не строить собственный редактор общего назначения и не выполнять миграцию без явной выгоды. Все ресурсы поставляются локально, без зависимости от CDN.

Критерий завершения: основные правки не теряются, программная вставка отменяется одним предсказуемым действием, внешний редактор не вызывает молчаливого перезаписывания файла.

## 2. Первый полезный выпуск подсказок Factorio

Первый срез: ручное Ctrl+Space в корневом control.lua, глобальные имена и defines.events из runtime-api.json версии игры, выбранной для мода.

- [ ] Выбрать источник API по установленной Factorio, соответствующей проекту/профилю. Показать используемую версию; при отсутствии подходящего описания предложить явно выбрать источник, не подставлять молча latest.
- [ ] Проверить фактическое наличие и схему runtime/prototype API JSON в поддерживаемых установках. Отсутствующие файлы, несовместимая схема и headless-установка должны приводить к понятному ограниченному режиму, а не поломке редактора.
- [ ] Создать общий индекс API: имена, типы, поля, методы, параметры, краткая документация, устаревшие элементы и ссылка на описание той же версии.
- [ ] Ctrl+Space — список подходящих вариантов; автоматическое открытие только в предсказуемых контекстах. Сортировать сначала точные и контекстные совпадения. Не навязывать дополнение обычного текста в комментариях и строках.
- [ ] Подсказка при наведении: краткое описание, тип/сигнатура, ограничение стадии, ссылка на полную документацию.
- [ ] Подсказка параметров вызова: текущий параметр, тип, обязательность; закрывается без изменения кода.
- [ ] Различать data/settings/runtime-контекст. Для общих Lua-модулей учитывать места подключения или показывать неопределённый контекст; не считать все файлы вне control.lua data-стадией.
- [ ] Начать с прямых обращений к известным глобальным объектам и простых локальных объявлений. Не обещать корректный вывод типов для произвольных alias, метатаблиц и динамического Lua.

Первый набор: data.raw, поля прототипов в уверенно определённом контексте, game, script, defines и события. Строки дополняются только в распознанных местах, где ожидается конкретный вид имени.

Критерий завершения: написать простой обработчик события и изменить рецепт, пользуясь списком имён, hover и параметрами; проверить корректность подсказок на двух поддерживаемых версиях игры. При недоступном API ввод, сохранение и обычная подсветка продолжают работать.

## 3. Подсказки по собственному моду и сборке

- [ ] Имена предметов, жидкостей, рецептов и технологий из доступного индекса проекта и итоговых данных выбранной сборки.
- [ ] В контекстах вроде ингредиента рецепта предлагать подходящий тип объекта, с иконкой при её наличии, внутренним именем и достоверной информацией об источнике.
- [ ] Подсказки путей require и ресурсов, ключей локализации — после поддержки базовых API-подсказок.
- [ ] Отмечать устаревший дамп сборки; не смешивать данные разных профилей, версий и startup-настроек. Статический индекс и итоговые игровые данные должны иметь различимые происхождение и полноту.
- [ ] Несохранённые правки текущего файла учитывать в локальных подсказках; внешний индекс обновлять по изменениям файлов без полного пересканирования при каждом символе.

Этот этап использует источник данных из [плана сборок](modpack-plan.md). Для обычного мода базовые подсказки должны работать и без создания сборки.

## 4. Навигация и диагностика

- [ ] Переход к локальному определению, существующему файлу require, ключу локализации и известному прототипу. Не угадывать файл-источник при отсутствии надёжной информации.
- [ ] Связь с графом прогрессии: из имени рецепта открыть его связи; из узла графа перейти в код или сведения об объекте.
- [ ] Более точную синтаксическую диагностику добавлять через проверенный парсер, поддерживающий выбранный диалект Lua. Не наращивать набор регулярных выражений до псевдо-компилятора.
- [ ] Разделять уверенную ошибку синтаксиса, предупреждение API и предположение статического анализа. Динамический Lua не должен становиться стеной ложных ошибок.
- [ ] Быстрые исправления — только локальные, проверяемые и отменяемые; для изменения нескольких файлов нужен предварительный diff.
- [ ] Команда открытия текущего файла/строки во внешнем редакторе; возвращение в FMStudio сохраняет текущие вкладки и обработку конфликтов.

Language server можно оценить позже, если локальные подсказки окажутся недостаточны. Это отдельное решение с затратами на процессы, поставку, версию Lua и рабочие области; оно не блокирует первый полезный выпуск.

## Дизайн и поведение

Сохранить текущие вкладки, расположение панели, темы, шрифтовую и цветовую систему. Встраивать небольшие панели дополнения, hover и параметров рядом с курсором, а не добавлять постоянные боковые панели. На узком экране подсказки остаются внутри видимой области; длинное описание раскрывается по запросу. Клавиши принятия дополнения работают только при открытом списке и не ломают обычные Enter/Tab. Описания API могут оставаться на языке источника; команды и состояния интерфейса переводятся существующим механизмом i18n.

## Технические границы и проверки

- Версионированный индекс API отделить от UI; редактор передаёт путь, версию документа, позицию и нужный контекст. Запоздавшие результаты не применяются к новому тексту или другой вкладке.
- Большие файлы получают явный ограниченный режим; индексирование и запросы не должны блокировать ввод. До выбора численных лимитов снять замеры на машине разработки и типичной сборке.
- Тесты: фильтрация и ранжирование дополнений, версия API, стадии, параметры вложенных вызовов, Unicode-позиции, устаревшие ответы, недоступный индекс и корректность отмены вставки.
- GUI-проверки: светлая/тёмная тема, узкая панель, масштаб 125/150%, клавиатура, скринридер, desktop и браузер. Проверить сочетание редактора с «Проблемами», файловым наблюдателем и внешним редактором.
- Никакого выполнения пользовательского Lua ради автодополнения. Игровой дамп — отдельное явное действие запуска выбранной сборки.

## Рекомендуемая последовательность задач

1. Тесты сохранности текста и прототип поля редактора; выбрать компонент или обоснованно оставить textarea.
2. Индекс одной установленной версии Factorio и ручной Ctrl+Space для известных глобальных имён.
3. Hover и параметры; контексты стадий и переключение версии API.
4. Контекстные имена рецептов/предметов и пути проекта.
5. Навигация, уточнённая диагностика и связь с графом сборки.

Первую поставку ограничить этапами 1–2 с небольшим рабочим набором подсказок. Оценивать её на реальной работе: сколько раз для правки рецепта или короткого runtime-скрипта пришлось уходить в другой редактор и почему. Сложные рефакторинги и отладка не являются причиной расширять этот выпуск.
